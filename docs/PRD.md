# 소담 AI 스튜디오 제품 요구사항 정의서(PRD)

| 항목 | 내용 |
| --- | --- |
| 문서 버전 | 1.0 |
| 작성일 | 2026-07-21 |
| 문서 상태 | 설계 승인본 · 구현 전 |
| 대상 제품 | 소담 AI 스튜디오(Sodam AI Studio) · 오픈놀 버전 |
| 주요 독자 | 제품 책임자, 개발팀, 디자인팀, 운영 담당자 |

## 1. 제품 개요

소담 AI 스튜디오는 한 줄의 아이디어에서 영상 기획, 스토리보드 이미지, 영상 제작과 내보내기까지 이어지는 AI 콘텐츠 제작 서비스다.

이번 버전은 기존의 **한 줄 텍스트 중심 영상 제작 흐름을 그대로 유지**하면서, 사용자가 자주 쓰는 캐릭터·제품·로고 등의 시각 자료를 개인 자산으로 축적하고 이미지와 영상 제작에 반복 활용할 수 있는 **통합 크리에이티브 자산 구조**를 추가한다.

인증은 Google 로그인을 유지한다. 최초 가입자는 개인정보 및 서비스 이용에 동의한 뒤 가입을 완료하며, 가입 완료 시 20크레딧을 받는다. 오픈놀 마스터는 가입 사용자 목록을 확인하고 총 60,000크레딧의 지급 누계 한도 안에서 특정 사용자에게 크레딧을 지급할 수 있다.

## 2. 배경과 문제 정의

### 2.1 현재 제품의 강점

- 영상 기획이 한 줄의 텍스트에서 시작해 진입 장벽이 낮다.
- Google OAuth 로그인이 구현되어 있다.
- 신규 가입자 20크레딧 초기화 로직이 데이터베이스 마이그레이션에 반영되어 있다.
- 스토리보드 이미지 생성 시 최대 5장의 레퍼런스 이미지를 캐릭터·제품·액세서리·배경으로 분류해 전달할 수 있다.
- 마스터 콘솔의 사용자 목록과 크레딧 현황 UI 기반이 있다.

### 2.2 해결해야 할 문제

- 현재 레퍼런스 이미지는 제작 시점에 매번 다시 추가해야 하며 사용자 자산으로 영구 관리되지 않는다.
- 캐릭터나 제품의 여러 시점·표정·형태를 하나의 재사용 가능한 자산으로 묶는 구조가 없다.
- 단건 이미지만 독립적으로 만들고 결과를 다음 제작에 재사용하는 흐름이 없다.
- 영상 기획 단계에서 특정 캐릭터·제품·로고를 명시적으로 선택해 기획과 스토리보드에 일관되게 연결할 수 없다.
- Google 로그인 안내문은 있으나 최초 가입자의 명시적 동의 상태와 약관 버전별 동의 이력을 관리하지 않는다.
- 마스터 화면의 실제 사용자 잔액 조회와 크레딧 지급 서버 로직이 완성되지 않았다.
- 과거 계획에 포함됐던 마스터의 계정 생성·정지·비밀번호 재발급은 Google 셀프가입 중심 방향과 맞지 않는다.

## 3. 제품 목표

1. 사용자가 Google 계정으로 간단히 가입하고 필수 동의를 완료하면 20크레딧으로 제작을 시작할 수 있게 한다.
2. 기존의 한 줄 영상 기획 경험을 유지하고, 개인 자산 선택은 항상 선택 사항으로 제공한다.
3. 사용자별로 완전히 분리된 개인 자산 보관함을 제공한다.
4. 캐릭터·제품의 복수 참고 이미지를 하나의 재사용 가능한 자산으로 관리한다.
5. 단건 이미지 제작과 영상 제작이 같은 개인 자산을 공유하게 한다.
6. 오픈놀 마스터가 가입 사용자를 조회하고 60,000크레딧 지급 누계 한도 내에서 크레딧을 지급하게 한다.
7. 모든 사용자 데이터와 자산에 서버 측 권한 검증을 적용한다.

## 4. 비목표 및 제외 범위

이번 범위에는 다음 기능을 포함하지 않는다.

- 마스터가 사용자 계정을 직접 생성하는 기능
- 사용자 계정의 정지 또는 활성화 기능
- 마스터가 사용자 비밀번호를 재발급하는 기능
- 마스터가 사용자 크레딧을 차감하거나 잔액을 강제로 설정하는 기능
- 사용자 간 자산 공유 또는 오픈놀 공용 자산 보관함
- 자산 협업, 댓글, 승인 워크플로우
- 캐릭터 음성 생성 및 음성 자산 관리
- 자산 컬렉션의 다단계 폴더 구조
- 마케팅 정보 수신 동의
- 모바일 네이티브 앱

기존 `profiles.status`, `profiles.login_id` 등의 레거시 컬럼은 호환성을 위해 즉시 삭제하지 않지만 신규 제품 기능에서는 사용하지 않는다. `master-create-account`, `master-reset-password` Edge Function은 호출 경로에서 제거하고 폐기 대상으로 관리한다.

## 5. 사용자와 권한

### 5.1 일반 사용자

- Google 계정으로 로그인한다.
- 최초 로그인 후 필수 동의를 완료한다.
- 한 줄 텍스트만으로 영상 기획을 시작할 수 있다.
- 본인의 자산만 생성·조회·수정·삭제할 수 있다.
- 본인의 자산을 단건 이미지와 영상 제작에 선택적으로 사용한다.
- 본인의 크레딧 잔액과 사용 이력을 확인한다.

### 5.2 오픈놀 마스터

- 일반 사용자와 동일하게 Google 계정으로 로그인한다.
- 서버에 저장된 `profiles.role = 'master'` 권한으로 마스터 기능에 접근한다.
- 가입을 완료한 일반 사용자 목록과 크레딧 정보를 조회한다.
- 사용자에게 크레딧을 지급한다.
- 전체 60,000크레딧 지급 누계와 잔여 지급 가능량을 확인한다.
- 다른 사용자의 개인 자산에는 접근할 수 없다.

마스터 권한은 클라이언트 이메일 비교가 아닌 데이터베이스 역할과 서버 측 권한 검사로 강제한다.

## 6. 핵심 제품 원칙

### 6.1 텍스트 우선, 자산은 선택 사항

영상 제작의 기본 진입점은 기존과 동일한 한 줄 아이디어 입력이다. 사용자가 자산을 선택하지 않아도 기획, 스토리보드, 영상 제작 전 과정이 정상 작동해야 한다.

### 6.2 한 번 만들고 반복 사용

업로드하거나 생성한 시각 자료는 개인 보관함에 저장할 수 있고, 이후 다른 이미지와 영상 프로젝트에서 다시 선택할 수 있어야 한다.

### 6.3 제작 흐름 간 일관성

영상 기획 단계에서 선택한 자산은 프로젝트에 연결되고, 기획 프롬프트와 스토리보드 이미지 프롬프트에 계속 반영되어야 한다.

### 6.4 명시적 저장

AI 생성 결과는 자동으로 영구 보관하지 않는다. 사용자가 `보관함에 저장`을 선택했을 때만 개인 자산으로 저장한다.

### 6.5 서버가 권한과 크레딧을 판정

자산 소유권, 마스터 역할, 크레딧 잔액과 지급 한도는 클라이언트 상태를 신뢰하지 않고 데이터베이스 정책 또는 서버 함수에서 검증한다.

## 7. 정보 구조와 주요 메뉴

| 메뉴 | 대상 | 역할 |
| --- | --- | --- |
| 영상 만들기 | 전체 사용자 | 기존 한 줄 아이디어 기반 영상 제작, 선택적 자산 연결 |
| 이미지 만들기 | 전체 사용자 | 자산 없이 또는 개인 자산을 활용한 단건 이미지 제작 |
| 자산 보관함 | 전체 사용자 | 캐릭터·제품·로고·일반 이미지 관리 |

| 사용자·크레딧 관리 | 마스터 | 가입 사용자 조회 및 크레딧 지급 |

## 8. 핵심 사용자 흐름

### 8.1 Google 최초 가입

1. 사용자가 `Google로 계속하기`를 선택한다.
2. Google OAuth 인증을 완료한다.
3. 시스템이 최신 필수 약관 동의 여부를 확인한다.
4. 미동의 사용자는 가입 절차 화면으로 이동한다.
5. 사용자가 필수 문서를 열람하고 각 항목에 동의한다.
6. 서버가 동의 문서 버전과 동의 시각을 기록한다.
7. 서버가 사용자 프로필과 20크레딧을 멱등하게 초기화한다.
8. 사용자가 영상 만들기 또는 이미지 만들기로 이동한다.

필수 동의를 완료하기 전에는 제작 기능, 개인 자산, 마스터 기능에 접근할 수 없다. 동의 화면 이탈 후 재로그인하면 동의 화면으로 복귀한다.

### 8.2 기존 사용자의 로그인

1. Google OAuth 인증 후 현재 약관 버전의 동의 여부를 확인한다.
2. 최신 필수 동의가 있으면 기존 작업 화면으로 이동한다.
3. 재동의가 필요하면 동의 화면으로 이동하되 기존 크레딧과 데이터는 유지한다.

### 8.3 한 줄 텍스트로 영상 만들기

1. 사용자가 한 줄 아이디어를 입력한다.
2. 자산을 선택하지 않고 바로 기획 생성을 실행한다.
3. 기존 기획·스토리보드·편집·내보내기 흐름을 진행한다.

이 흐름은 자산 기능 도입 전의 기본 사용성을 그대로 보존한다.

### 8.4 개인 자산을 활용해 영상 만들기

1. 사용자가 한 줄 아이디어를 입력한다.
2. `자산 추가`에서 본인의 캐릭터·제품·로고·일반 이미지를 선택한다.
3. 시스템이 자산의 이름과 설명을 영상 기획 입력에 구조화해 추가한다.
4. 프로젝트와 선택 자산의 연결 관계를 저장한다.
5. 스토리보드 이미지 생성 시 연결된 자산의 대표·참고 이미지를 레퍼런스로 전달한다.
6. 사용자는 프로젝트 중간에 연결 자산을 추가하거나 해제할 수 있다.

### 8.5 단건 이미지 만들기

1. 사용자가 독립된 `이미지 만들기` 화면에 진입한다.
2. 프롬프트를 입력한다.
3. 필요하면 개인 보관함 자산을 선택한다. 자산 선택은 필수가 아니다.
4. 이미지 모델과 화면비를 선택한다.
5. 시스템이 예상 크레딧 비용을 생성 전에 표시한다.
6. 사용자 확인 후 이미지 한 장을 생성한다.
7. 생성 성공 시에만 크레딧을 차감한다.
8. 사용자는 결과를 다운로드, 다시 생성 또는 보관함에 저장한다.
9. 저장 시 자산 이름, 분류와 설명을 입력하고 기존 자산에 참고 이미지로 추가하거나 새 자산으로 만든다.

### 8.6 개인 자산 만들기

1. 사용자가 `자산 보관함`에서 새 자산을 선택한다.
2. 캐릭터, 제품, 로고, 일반 이미지 중 분류를 선택한다.
3. 이름과 설명을 입력한다.
4. 직접 파일을 업로드하거나 단건 이미지 생성 결과를 선택한다.
5. 캐릭터·제품은 대표 이미지 한 장과 추가 참고 이미지를 묶는다.
6. 로고는 투명 배경을 포함할 수 있는 원본 이미지 한 장을 기본으로 저장한다.
7. 일반 이미지는 한 장을 저장하며 스타일·배경 레퍼런스로 사용할 수 있다.

### 8.7 마스터의 사용자 크레딧 지급

1. 마스터가 `사용자·크레딧 관리`에 진입한다.
2. 가입 완료 사용자 목록을 검색하거나 정렬한다.
3. 대상 사용자를 선택하고 지급량과 사유를 입력한다.
4. 화면이 전체 한도, 누적 지급량, 지급 후 잔여량을 보여준다.
5. 서버가 마스터 역할, 양수 지급량, 사용자 존재 여부와 잔여 한도를 검증한다.
6. 서버가 사용자 잔액 증가와 거래 이력 생성을 하나의 트랜잭션으로 처리한다.
7. 화면이 갱신된 사용자 잔액과 마스터 잔여 지급 가능량을 표시한다.

## 9. 기능 요구사항

### 9.1 인증과 가입 동의

| ID | 요구사항 |
| --- | --- |
| AUTH-01 | 로그인 방법은 Google OAuth를 유지한다. |
| AUTH-02 | 최초 Google 로그인 후 필수 가입 동의 화면을 표시한다. |
| AUTH-03 | 필수 항목은 서비스 이용약관, 개인정보 수집·이용, AI 콘텐츠 생성 및 업로드 자료 처리 안내로 구성한다. |
| AUTH-04 | 동의 이력은 사용자, 문서 종류, 문서 버전, 동의 시각을 저장한다. |
| AUTH-05 | 현재 문서 버전에 동의하지 않은 사용자의 제작 기능 접근을 차단한다. |
| AUTH-06 | 가입 완료 시 20크레딧을 한 번만 지급한다. |
| AUTH-07 | OAuth 콜백 재시도, 새로고침, 중복 요청으로 프로필·동의·크레딧이 중복 생성되지 않아야 한다. |
| AUTH-08 | 기존 사용자의 크레딧과 프로젝트는 재동의 과정에서 변경하지 않는다. |

### 9.2 사용자·크레딧 관리

| ID | 요구사항 |
| --- | --- |

### 10.2 기존 데이터 재사용

- `profiles`: Google 사용자 프로필과 `role`을 재사용한다.
- `user_credits`: 현재 잔액과 최대 크레딧 데이터를 재사용한다.
- `credit_transactions`: 가입 지급, 마스터 지급, 생성 차감, 환불 이력을 저장한다.
- `projects`: 기존 영상 프로젝트를 유지한다.
- `admin_config`: MVP에서는 마스터 총 지급 한도 `60000`을 저장하는 데 재사용할 수 있다.

마스터 지급 누계는 `credit_transactions`에서 `type = 'manual_grant'`인 양수 거래의 합으로 계산한다. 가입 보너스는 `type = 'signup_bonus'`로 구분해 누계에서 제외한다. 지급과 누계 검증은 전용 서버 RPC로 처리한다.

## 11. 권한과 보안 요구사항

- 모든 제작 화면은 인증과 최신 필수 동의를 확인해야 한다.
- 마스터 UI 노출 여부와 무관하게 모든 마스터 API가 `is_master()` 또는 동등한 서버 검사를 수행해야 한다.
- 일반 사용자는 다른 사용자의 프로필 목록, 크레딧, 거래 이력과 자산을 조회할 수 없어야 한다.
- 마스터는 사용자·크레딧 운영 정보에는 접근할 수 있지만 개인 자산 파일에는 접근할 수 없어야 한다.
- 자산 조회·수정·삭제는 `owner_id = auth.uid()` 조건을 데이터베이스 RLS에서 강제한다.
- Storage 객체 경로는 사용자 ID로 분리하고 Storage 정책에서도 소유권을 검사한다.
- 업로드 파일의 MIME 형식, 용량과 확장자를 서버에서 검증한다.
- AI API 키와 외부 서비스 비밀키를 브라우저로 전달하지 않는다.
- 크레딧 차감·환불·지급은 재시도 키 또는 동등한 멱등성 장치를 사용해 중복 거래를 막는다.
- 동의 기록은 사용자가 자산을 삭제하더라도 법적·운영 보존 정책에 따라 별도로 관리한다.

## 13. 수용 기준

### 13.1 가입

- 신규 Google 사용자가 세 가지 필수 항목에 동의하기 전에는 제작 화면에 들어갈 수 없다.
- 동의 완료 후 잔액이 정확히 20크레딧이 된다.
- 동일 계정으로 여러 번 로그인해도 가입 보너스는 한 번만 지급된다.
- 동의한 문서 버전과 시각을 관리자 데이터에서 확인할 수 있다.

### 13.2 마스터

- 일반 사용자가 마스터 URL이나 RPC를 직접 호출하면 접근이 거절된다.
- 마스터 사용자 목록의 이메일, 이름, 가입일과 잔액이 실제 데이터와 일치한다.
- 59,990크레딧을 지급한 상태에서 11크레딧 추가 지급은 실패하고 어떤 잔액도 변경되지 않는다.
- 사용자가 지급받은 크레딧을 모두 사용해도 마스터 잔여 지급 가능량은 증가하지 않는다.
- 사용자 화면에 계정 생성, 정지·활성화, 비밀번호 재발급, 차감·잔액 설정 동작이 존재하지 않는다.

### 13.3 자산 보관함

- 사용자 A가 생성한 자산은 사용자 B의 목록과 직접 API 호출 모두에서 보이지 않는다.
- 캐릭터와 제품 자산에 대표 이미지와 추가 참고 이미지를 저장하고 순서를 변경할 수 있다.
- 로고 원본을 저장하고 다음 이미지 또는 영상 제작에서 선택할 수 있다.
- 자산 이름 검색과 분류 필터가 함께 작동한다.
- 자산 삭제 시 연결 프로젝트 수를 표시하고 확인 전에는 삭제하지 않는다.

### 13.4 단건 이미지

- 자산을 선택하지 않고 프롬프트만으로 이미지 한 장을 생성할 수 있다.
- 개인 자산을 선택해 해당 자료를 레퍼런스로 이미지 한 장을 생성할 수 있다.
- 생성 전에 비용을 확인할 수 있고 잔액 부족 시 생성할 수 없다.
- 성공 결과를 새 자산 또는 기존 캐릭터·제품의 참고 이미지로 저장할 수 있다.
- 저장하지 않은 생성 결과가 자산 보관함에 자동 등록되지 않는다.

### 13.5 영상 제작

- 자산을 하나도 선택하지 않고 기존 한 줄 아이디어 흐름을 끝까지 진행할 수 있다.
- 자산을 선택한 경우 해당 이름과 설명이 기획 결과에 반영된다.
- 같은 캐릭터 자산이 프로젝트의 여러 스토리보드 이미지 생성 요청에 반복 전달된다.
- 자산 이미지와 장면별 임시 레퍼런스의 합이 모델 입력 한도를 넘으면 정해진 우선순위로 최대 5장만 전달된다.

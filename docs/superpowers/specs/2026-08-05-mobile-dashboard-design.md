# 모바일 메인 대시보드 개편 설계

## 목적

로그인 후 첫 화면을 모바일 사용자가 한눈에 이해하고 바로 제작을 시작할 수 있는 `제작 시작형` 대시보드로 개편한다. 현재 프로젝트 관리 기능은 유지하되, 모바일에서는 쇼츠·이미지·영상·음성 제작 진입점을 우선 노출한다.

## 범위

- 로그인 후 `Dashboard`와 대시보드 상태에서의 콘텐츠 레이아웃만 수정한다.
- 사이드바, 개별 제작 스튜디오, 프로젝트 제작 단계의 내부 화면은 변경하지 않는다.
- 데스크톱의 기존 프로젝트 3열 구조와 주요 동작은 유지한다.
- 오픈 이벤트 팝업의 주 CTA 문구는 `지금 신청하기`에서 `신청하기`로 변경한다.

## 화면 구성

### 모바일 상단

- 영문 대형 제목 `MY PROJECTS`를 모바일에서 `무엇을 만들어볼까요?`로 교체한다.
- 설명은 `AI 쇼츠부터 이미지·영상·음성까지 한곳에서 시작하세요.`로 갱신한다.
- `새 프로젝트` 버튼을 제목 아래의 가로 전체 폭 주 CTA로 배치한다.
- 버튼의 글자와 아이콘은 한 줄을 유지하고 최소 44px 이상의 터치 영역을 확보한다.

### 제작 도구 바로가기

- `이미지 생성`, `영상 생성`, `음성 생성` 바로가기를 3개의 동일한 카드로 배치한다.
- 각 카드는 기존 `IMAGE_STUDIO`, `VIDEO_STUDIO`, `VOICE_STUDIO` 화면으로 이동한다.
- 모바일에서는 한 줄 3개를 유지하되 짧은 한글 라벨과 아이콘으로 빠르게 구분한다.
- 데스크톱에서는 상단 CTA 옆이나 아래에 자연스럽게 정렬하되 프로젝트 영역보다 과도하게 커지지 않게 한다.

### 프로젝트 영역

- 프로젝트가 있으면 제목을 `최근 프로젝트`로 표시하고 최근 3개를 우선 노출한다.
- 모바일 프로젝트 카드는 한 열로 배치하고 내부 패딩과 썸네일 높이를 줄여 스크롤 부담을 낮춘다.
- 프로젝트가 없으면 `아직 만든 프로젝트가 없어요`와 `아이디어만 준비되면 AI가 제작 과정을 도와드려요.`를 표시한다.
- 빈 상태에서는 상단의 `새 프로젝트` CTA를 중복 배치하지 않는다.

### 제작 의뢰 현황

- 데스크톱에서는 기존 표를 유지한다.
- 모바일에서는 프로젝트명, 날짜, 상태가 한 카드 안에서 읽히는 세로 목록으로 전환한다.
- 의뢰 목적은 공간이 허용될 때 한두 줄로 보이며, 상태 배지는 오른쪽 상단에 유지한다.

## 반응형 규칙

- 기준 모바일 폭은 390px과 430px이다.
- 768px 미만에서는 모바일 제목, 세로 CTA, 한 열 프로젝트 카드, 카드형 의뢰 현황을 사용한다.
- 768px 이상에서는 기존 데스크톱 제목과 프로젝트 그리드를 유지한다.
- 모든 화면에서 가로 스크롤이 발생하지 않아야 한다.

## 컴포넌트와 데이터 흐름

- 기존 `Dashboard`가 프로젝트와 제작 의뢰 데이터를 계속 로드한다.
- 제작 도구 바로가기는 기존 Zustand `setStep`을 사용하며 새로운 라우팅이나 상태를 추가하지 않는다.
- 프로젝트 생성, 열기, 삭제, 더보기, 인트로 설문과 온보딩 투어 동작은 그대로 유지한다.
- 사용자에게 보이는 새 문구는 한국어·영어 번역 파일에 함께 추가해 현재 다국어 구조를 보존한다.

## 접근성과 오류 처리

- 바로가기 카드는 `button` 요소와 명확한 접근성 이름을 사용한다.
- 삭제 버튼과 새 프로젝트 버튼의 기존 키보드 동작을 보존한다.
- 데이터 조회 실패 처리 방식은 현재 동작을 유지하고 이번 변경에서 별도 오류 상태를 추가하지 않는다.
- 상태 색상만으로 의미를 전달하지 않고 텍스트 라벨을 함께 표시한다.

## 테스트와 완료 기준

- E2E 테스트에서 모바일 제목, 설명, 주 CTA, 3개 제작 도구 바로가기를 확인한다.
- 390px과 430px에서 문구가 세로로 쪼개지지 않고 문서 폭이 뷰포트를 넘지 않는지 확인한다.
- 제작 도구 바로가기를 클릭하면 각 스튜디오 화면으로 이동하는지 확인한다.
- 프로젝트가 없는 상태와 프로젝트·의뢰가 있는 상태의 모바일 레이아웃을 각각 확인한다.
- 기존 팝업과 사이드바 회귀 테스트 및 프로덕션 빌드를 통과해야 한다.
- 데스크톱과 모바일 스크린샷을 검토하고 시각 점수 90점 이상을 완료 기준으로 삼는다.

## 제외 사항

- 새 백엔드 API, 데이터베이스 변경, 새 패키지 추가는 하지 않는다.
- 개별 이미지·영상·음성 스튜디오의 모바일 UI는 이번 범위에 포함하지 않는다.
- 랜딩 페이지와 관리자 화면은 변경하지 않는다.

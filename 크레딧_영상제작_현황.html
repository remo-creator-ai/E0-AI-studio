1. 영상제작이 붙어 있는가?

현재 제공 범위(확정) 스토리보드 제작까지만 제공. 영상제작(즉시 렌더링)은 기존 게이팅 그대로 차단 유지합니다.

영상 파이프라인 자체는 코드상 완결되어 실제 AI 비디오 API와 연동되어 있으나(Mock 아님), 사용자 진입은 Coming Soon 모달로 막혀 있습니다. 사용자에게 열린 것은 스토리보드 결과물 내보내기(다운로드)와 이메일 발송까지입니다.

차단 메커니즘 (코드 변경 없이 유지): showComingSoonModal 초기값 true (ProductionStep.tsx:86) → PRODUCTION 단계 진입 즉시 모달이 전체를 덮음. 모달을 벗어나는 두 경로(닫기 · 의뢰 폼 제출)가 모두 ASSEMBLY로 복귀 (:948-950, :1213-1214) → Render / 배치 렌더 UI에 도달하는 정상 경로가 없어 영상제작은 완전 차단.
범위 정의: 사이트 안에서 특정 유저를 지정해 제작을 의뢰하거나 의뢰를 수신하는(유저 간 의뢰) 행위는 범위에서 제외됩니다. 사용자가 할 수 있는 것은 스토리보드 결과물의 내보내기(export)와 이메일 발송에 한정됩니다.

차감 동작 방식

  • 선차감 아님 · 성공 후 차감: 생성 API가 성공 반환한 뒤에 deduct() 호출 → 실패 시 크레딧 소모 없음.
  • 사전 잔액 확인: 각 작업 전 hasEnough(cost)로 검사, 부족 시 경고 후 중단.
  • 백엔드 원자적 차감: Supabase RPC deduct_credits가 서버에서 검증(음수면 잔액 부족).
  • 배치 업스케일: 대상 컷 수 × 단가 총합을 한 번에 확인 후 순차 진행.

3. 논의가 필요한 지점

① 스토리보드 과금 단위 = "컷"이 아니라 "3×3 그리드 1장"

스토리보드는 개별 컷이 아니라 3×3 매트릭스 시트 단위로 생성·과금됩니다. 기본 모델 기준 그리드 1장 = 3 크레딧 → 컷당 실효 비용은 매우 낮음.
논의: 과금을 "컷당"으로 볼지 "시트당"으로 볼지, 가격 커뮤니케이션 기준을 통일할 필요.

② 영상이 압도적 비용 드라이버 (이미지의 6~50배)

이미지 2~5 vs 영상 30~100. 영상 1편(예: 8컷)을 VEO로 뽑으면 800 크레딧.
논의: "Coming Soon" 게이팅과도 직결 — 즉시 렌더링을 열 때 1인당 영상 한도/과금 정책을 먼저 확정해야 함.

③ 정의는 됐으나 미사용인 VIDEO_ULTRA = 250

상수와 설정 화면 가격표에는 있으나, 실제 엔진 분기(getVideoCreditCost)는 Kling/VEO 두 가지만 매핑.
논의: ULTRA 티어를 실제 출시할지, 아니면 표기에서 제거할지.

④ 이미지 단가 정의가 두 곳에 중복

CREDIT_COSTS.IMAGE_PRO/STANDARD (5/2) 와 IMAGE_MODEL_INFO[].creditCost (3/5/2) 가 별개로 존재. 실제 스토리보드 생성은 후자만 사용.
논의: 단일 소스로 통합해 불일치·유지보수 리스크 제거.

1계정 체계 (3-Tier)

개발사 리모(REMO)가 최상위이며, 고객사 오픈놀에게 마스터 계정 1개를 발급합니다. 오픈놀 마스터가 내부적으로 최대 20개의 아이디/비번 계정을 생성·관리합니다.

2인증 방식 변경

AS-IS (제거)
  • Google OAuth 단독 signInWithGoogle()
  • 누구나 구글 계정으로 셀프 가입
  • 첫 로그인 시 크레딧 60 자동 지급
TO-BE (신규)
  • 아이디 / 비밀번호 로그인만 허용
  • 셀프 가입 불가 — 마스터가 발급한 계정만
  • 크레딧은 마스터가 수동 부여 (기본값 0 또는 지정)
  • Google 버튼·회원가입 화면 전면 제거
구현 메모: Supabase Auth는 이메일 기반이므로, 아이디를 {아이디}@sodam.local 형태 합성 이메일로 매핑해 email/password 인증을 그대로 활용하는 방식을 제안(별도 비밀번호 해싱 불필요). 계정 생성은 마스터가 service-role Edge Function으로 호출.

5데이터 모델 변경

테이블 / 객체변경내용
masters 신규(단일) 오픈놀 단일 행 고정. id, name('오픈놀'), max_accounts(20), credit_quota(60000). credit_quota = 발급계정에 부여 가능한 총 크레딧 한도(임시 6만) · REMO만 변경. 부여 시 배분누계 ≤ quota 검증.
accounts / profiles 신규 발급 계정. user_id(auth), username(마스터 지정), display_name, status(active/suspended), created_by. 20개 상한 트리거.
user_credits 재활용 그대로 사용. 신규 계정 기본값 60 고정(기존값 유지).
credit_transactions 재활용 manual/bonus 타입 이미 존재 → 마스터 부여/수정 로그로 그대로 사용. 사용이력 화면의 데이터 소스.
production_requests 컬럼 추가 기존 재활용 + recipient_email(수신 주소) 컬럼 추가 → “어디 주소로”. 값은 고정 운영 주소 1개를 서버에서 주입(사용자 미입력). requester_name/email, purpose, created_at, status는 이미 존재.
RPC / Edge Fn 신규 master_create_account, master_set_credits, master_list_accounts, master_get_usage (service-role, 마스터 권한 검증). 의뢰 조회는 기존 admin_get_all_requests 재활용(마스터 단일이므로 전체 조회).
RLS 정책 확장 마스터는 전체 계정/크레딧/의뢰 조회. 발급 계정은 본인 데이터만(기존 정책 유지).
authStore 교체 signInWithGoogle 제거 → signInWithPassword(username→합성이메일). 셀프 가입 UI 제거.
